这套流程解决什么

目标很具体：平时只写 Markdown，运行一条命令，网站自动生成并发布到 GitHub Pages。域名、HTTPS 和后续内容更新都不需要每次重新配置。

这套方案适合愿意维护少量代码、希望文章仍然掌握在自己文件里的人。如果你完全不想接触终端，可以在最后了解本地内容输入工具，但底层流程仍然是下面这些步骤。

What this workflow solves

The goal is concrete: write Markdown, run one command, and publish the generated site to GitHub Pages. The domain, HTTPS and routine content updates should not require a new setup every time.

This approach is for people who are comfortable maintaining a small amount of code and want to keep their writing in local files. A content input tool can reduce the command-line work later, but the publishing pipeline remains the same.

好的发布流程不是让技术变得更复杂，而是让你不再为重复操作分心，把精力留给内容本身。

A good publishing workflow does not add complexity. It removes repeated work so attention can return to the writing.
