    Knowing the Store: What a Memory Backend Must Write Down Before an Agent Can Read It

    Knowing the Store: What a Memory Backend Must Write Down Before an Agent Can Read It

    为什么推给你：Agent 工程（命中：上下文、context、memory、记忆）

    Why it is here: Agent engineering (matched: 上下文, context, memory, 记忆)

    这篇论文问的是「Agent 在检索之前该知道什么」：长期记忆 Agent 可能凭一条早该停用的记录作答（例如用户后来取消的计划），而记忆库要暴露哪些信息，Agent 才能在不检索的情况下判断这条记录是否还用得上，作者把这称为元记忆监控（metamemory monitoring）[32]。做法是把每个问题对着同一记忆库的三个版本各问一次，三个版本只差一个属性，因此措辞无法泄露答案；读者只看到一个不含数值的摘要：按生命周期状态统计的记录数与属性名列表。结果是：在基准真值产生的短列表（平均 2.6 个属性名）上，五个语言模型没有一个能稳定胜过「对属性名做余弦相似度检索」这个朴素基线；把列表填充到 60 个名字后，朴素基线掉 0.18，而 GPT-5.6 Luna 与 Sol 只掉 0.06–0.07 并领先 0.13–0.14。对做 Agent 记忆的团队，参考价值是记忆后端的接口设计本身就是能力上限，暴露「状态计数 + 属性名」这类轻量元信息可能比把内容塞进上下文更有效；限制是结论建立在合成记忆库与单一评测协议上，真实库的噪声与多用户场景还需验证。

    This paper asks what an agent should know before it retrieves anything: a long-term-memory agent can answer from a record it should no longer use — a plan the user later cancelled — so what must a memory store expose for the agent to judge that beforehand, which the authors score as metamemory monitoring[32]. Each of 148 questions is asked against three versions of one store differing in a single attribute, so wording cannot leak the answer, and the reader sees only a value-free summary: record counts by lifecycle state plus a list of attribute names. On the short lists the ground truth produces (2.6 names on average), none of five language models reliably beats a cosine-similarity lookup over the names; padded to 60 names the lookup loses 0.18 while GPT-5.6 Luna and Sol lose only 0.06–0.07 and lead by 0.13–0.14. For memory teams the reference is that the store's interface design sets the capability ceiling, so exposing lightweight metadata such as state counts and attribute names may beat stuffing content into context; the limit is a synthetic store and a single protocol, leaving real-world noise and multi-user settings unverified.

    边界：限制是结论建立在合成记忆库与单一评测协议上，真实库的噪声与多用户场景还需验证。

    Organising Trajectory Evidence for Language-Model Agent Assurance

    为什么推给你：Agent 工程（命中：上下文、context、benchmark）

    Why it is here: Agent engineering (matched: 上下文, context, benchmark)

    这篇论文解决的是 Agent 保证（assurance）证据无法合并的问题：日志规则检查、技能覆盖分析、支持检查、前缀监控、执行门与稀有事件估计各自只看一次运行的一部分，作出的断言强度也不同，但没有统一的说法说明这些断言如何组合、又漏了什么[34]。做法是给出一套基于逻辑、信息片段（fragments）与保证账本（assurance ledger）的框架：需求写成两层逻辑的公式——外层是记录事件上的有限迹时序逻辑，内层是「决策时 Agent 所记录上下文是否支持该结论」的立场逻辑；评估者、Agent 与执行门各自只能看到这套语言的某个片段，每种检查方法判定一个片段并返回带类型的断言（精确、在指定测试集上成立、风险界、或描述性），账本再把证据合并，把每条义务分类为「已确立 / 已处理但未确立 / 未处理」。效果上，在 456 条公开的 τ²-bench 电信轨迹上，基准 oracle 标出 231 条，加入规则检查器、支持替代与前缀监控基线后并集依次升到 391、401、407，各自都贡献了别人漏掉的标记，而执行门能把某条禁令在受门控部署上变成「精确」。对做 Agent 上线审计的团队，参考价值是把「检查能证明什么」显式形式化，而不是把一堆工具的输出拼在一起当安全证明；限制是这套逻辑需要为每条义务人工建模，49 条未被标记的运行与未满足义务的边界仍是开放问题。

    This paper addresses the inability to combine agent assurance evidence: log rule checkers, skill coverage analyses, support checkers, prefix monitors, execution gates and rare-event estimators each observe part of a run and make claims of different strength, but nothing says how these claims combine or what they leave unchecked[34]. The proposal is a framework built on a logic, information fragments and an assurance ledger: requirements become formulas of a two-tier logic — an outer finite-trace temporal logic over recorded events and an inner logic of standing about what the agent's recorded context supports at a decision — with the assessor, the agent and the gate each seeing a fragment, every checking method deciding one fragment and returning a typed claim (exact, on a named suite, a risk bound, or descriptive), and the ledger merging evidence to classify each obligation as established, addressed but not established, or unaddressed. For teams auditing agent deployments the reference is to formalise what each check proves instead of pasting tool outputs into a safety claim; the limit is that every obligation needs manual modelling, and the 49 unflagged runs remain an open boundary.

The reference for agent teams is to audit which knowledge was wrongly put into memory rather than documents; the caveat is that this is argument rather than evidence, and documents are not equivalent to memory for historical state.
