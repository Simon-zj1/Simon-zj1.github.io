    Dynamic Harness Search: Building Multi-Agent Systems Per-Query via Prediction

    Dynamic Harness Search: Building Multi-Agent Systems Per-Query via Prediction

    为什么推给你：Agent 工程（命中：harness、编排、multi-agent）

    Why it is here: Agent engineering (matched: harness, 编排, multi-agent)

    SHIFT 针对的是 harness 设计的两难：角色、指令、工具与通信结构的价值只有跑起来才知道，所以为每个查询定制 harness 要么在推理时把多个方案都执行一遍，要么靠昂贵的人工设计[31]。它的做法是把执行移出「每查询搜索」的循环：先用搜索让本地 LLM 架构师学到一个构建 harness 的策略，再学一个价值函数，从已有的执行记录里预测「准确率与执行成本」的权衡，最后对每个查询用蒙特卡洛树搜索搭出 harness。效果是在六个基准、9,193 个任务上（执行器为 Gemini 3.5 Flash）平均准确率约 80%，比 17 个基线中最强的高出 7.2 个百分点；低成本模式在少用 32% token 的情况下准确率仍高于所有基线，并且联合选择结构、指令与工具比只选其一最多高 9.1 个百分点。对做多 Agent 编排的团队，参考价值是把 harness 设计当成可预测的搜索问题而不是一次性工程；限制是价值函数依赖训练时的执行分布与执行器特性，换模型或任务族后需要重新校准预测。

    SHIFT attacks a dilemma in harness design: roles, instructions, tools and communication structure only reveal their value through execution, so tailoring a harness per query means either running alternatives at inference or expensive manual design[31]. It moves execution out of the per-query search loop: a local LLM architect first learns a policy over harness-building actions from search, a value function predicts the accuracy-versus-cost trade-off from measured executions, and Monte Carlo tree search then constructs a harness for each query. For multi-agent teams the reference is treating harness design as a predictable search problem rather than one-off engineering; the limit is that the value function depends on the training execution distribution and executor, so predictions need recalibration after switching models or task families.

    CUAWright: A Minimal Unified Interface for Digital Agents

    CUAWright: A Minimal Unified Interface for Digital Agents

    为什么推给你：Agent 工程（命中：harness、上下文、context、benchmark）

    Why it is here: Agent engineering (matched: harness, 上下文, context, benchmark)

    这篇论文质疑「电脑操作 Agent」的通行架构：模型通常被套在一个领域专用的 harness 里，界面与工具在任务执行前就固定下来，GUI 原生与静态工具集让模型无法直接对系统状态做程序化操作，也无法灵活造工具[32]。它的解法是把接口压到最小：约 3,000 行代码的终端 harness，只用 bash 命令作为动作接口，把文件系统当作动态造工具与管理上下文的可演化空间。效果上，统一的可编程接口全面优于 GUI 或混合 CLI 接口：在 OSWorld 2.0 上部分奖励相对提升 33.2%、估算成本下降 37.5%（对比公开的 GPT-5.5 基线）；Online-Mind2Web 与长程 Odysseys 的成功率分别高出 GUI 原生 harness 4.7% 与 44.0%，在需要视觉理解与 CLI 交互的 CAD 任务上比其它 CLI harness 高出 8.1%–41.6%。对做 computer-use Agent 的团队，参考价值是先问「接口是否够小够通用」，再决定要不要堆 GUI 工具；限制是纯 bash 接口把风险集中到命令执行上，论文未给出沙箱与回滚机制，真实部署仍需自行加固。

    This paper questions the standard architecture of computer-use agents: a model is wrapped in a domain-specific harness whose interface and human-engineered tools are fixed before execution, and a GUI-native, static harness prevents direct programmatic operation on system state or flexible tool construction[32]. The fix shrinks the interface: a roughly 3,000-line terminal harness using bash commands as the sole action interface, with the file system as an evolvable space for creating tools and managing context. The unified programmable interface beats GUI or hybrid CLI interfaces across tasks: on OSWorld 2.0 a 33.2% relative gain in partial reward with 37.5% lower estimated cost against the published GPT-5.5 baseline, and on Online-Mind2Web and the long-horizon Odysseys benchmark success rates 4.7% and 44.0% above a GUI-native harness, with 8.1%–41.6% relative gains on CAD benchmarks over other CLI harnesses. For computer-use teams the reference is to ask whether the interface is small and general enough before piling on GUI tools; the limit is that a pure bash interface concentrates risk in command execution, and no sandboxing or rollback mechanism is described.

Show HN's Offrun collects coding agents scattered across terminals, IDEs and cloud sandboxes into a single workspace for dispatching tasks, watching status and collecting results[2]. It organises sessions as workspace-plus-task and funnels every agent's output into one place for a human or the next agent. The takeaway for developers running several coding agents is to treat parallelism as scheduling and observability, not prompting; the caveat is that it is early, and the 86 HN comments still argue about isolation and safety boundaries.
