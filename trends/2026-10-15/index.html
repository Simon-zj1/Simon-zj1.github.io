    AdaRSI: On-Demand Recursive Self-Improvement for Embodied Agents

    AdaRSI: On-Demand Recursive Self-Improvement for Embodied Agents

    为什么推给你：机器人与具身智能（命中：vla、仿真、simulation）

    Why it is here: Robotics and embodied AI (matched: vla, 仿真, simulation)

    论文针对的是具身 Agent 的递归自我改进（RSI，Recursive Self-Improvement）该改哪一层这个问题：预训练 VLA（Vision-Language-Action，视觉—语言—动作）模型在没见过的长程任务里常常半途失败，而现有做法要么只改冻结执行器外面的脚手架（结果加不进缺失的动作），要么对持续失败盲目微调执行器权重（却没判断失败到底出在「怎么调用」还是「根本不会」）。AdaRSI 的做法是让编码 Agent 先改进自己的技能与 harness，再把持续失败的子步骤从保存的状态出发重试以做归因，只有在归因显示缺失能力时才更新执行器权重。它要解决的核心是「何时该改权重、何时只改调用方式」，把昂贵的权重更新留到真正必要的时候。效果上论文给出的对比基线是上述两类 RSI 方法，关键收益是避免了在脚手架可修的情况下误改权重；限制是归因依赖从保存状态重试，状态不可恢复的任务上该机制失效，且实验集中在仿真与有限真机任务，泛化性仍需验证。

    This paper asks which layer recursive self-improvement (RSI) should change in embodied agents: pretrained VLA (vision-language-action) models often fail midway through unseen long-horizon tasks, and existing approaches either refine the harness around a frozen executor (so a missing motion can never be added) or train the executor on persistent failures without asking whether the failure lies in how it is called or in what it can do. AdaRSI has a coding agent first improve its own skills and harness, then attribute persistent failures by retrying failing sub-steps from saved states, updating executor weights only when attribution shows a missing capability. The crux is deciding when to change weights versus only how they are invoked, reserving expensive updates for cases that need them. Against those two baseline RSI families the reported gain is avoiding weight updates when the harness was the fixable part; the limitation is that attribution depends on replaying from saved states, so tasks without recoverable state break the mechanism, and the experiments concentrate on simulation plus limited real-robot tasks, leaving generalisation unverified.

    SwarmRSI: Recursive Self-Improvement through Evolving Scientific Agent Swarm

    SwarmRSI: Recursive Self-Improvement through Evolving Scientific Agent Swarm

    为什么推给你：Agent 工程（命中：评测、multi-agent）

    Why it is here: Agent engineering (matched: 评测, multi-agent)

    论文针对的是科研多 Agent 系统里「实验失败之后该改哪里」的归因难题：科学 Agent 群（swarm）可以把不同研究方向的证据与实现组合起来指导后续实验，但实验结果差的时候，无法判断该修订假设还是修订实现，而整体评分又会掩盖对别的 Agent 有用的局部组件。SwarmRSI 给出的框架包含 Feedback-Guided Swarm Mutation：用带引导的反馈同时精修假设与其实现，而不是把两者当成同一个黑箱，从而让「假设错了」和「代码写错了」在变异算子里被区别对待。它要解决的是多 Agent 自我改进中的信用分配问题，把可复用的中间实现保留下来而不是随整体分数一起被淘汰。效果上论文给出的对比基线是既有的科研 Agent 与 RSI 方法；限制是这类方案的评测高度依赖任务域的评分函数，换到没有稳定评分器的科研场景时引导信号可能失真，且算力开销随族群规模上升。

    The paper addresses attribution in scientific multi-agent systems — where to fix things after an experiment fails: a scientific agent swarm can combine evidence and implementations from different research directions to guide later experiments, but weak results leave unclear whether to revise a hypothesis or its implementation, while aggregate program scores hide components that other agents could reuse. SwarmRSI introduces Feedback-Guided Swarm Mutation, refining hypotheses and their implementations together under guided feedback rather than treating both as one black box, so 'the hypothesis is wrong' and 'the code is wrong' are handled differently by the mutation operator. The problem it really solves is credit assignment in multi-agent self-improvement, keeping reusable intermediate implementations alive instead of discarding them with a bad aggregate score. Its comparison baseline is existing scientific-agent and RSI methods; the limitation is that such approaches depend heavily on the task domain's scoring function, so the guidance signal can distort in research settings without a stable scorer, and compute cost grows with swarm size.
