    Cache Engineering for Agents

    Cache Engineering for Agents

    为什么推给你：Agent 工程（命中：上下文、context、benchmark）

    Why it is here: Agent engineering (matched: 上下文, context, benchmark)

    Cache Engineering for Agents 针对 Agent 长轨迹下 KV 缓存成为主要成本的问题：轨迹越长，缓存的 I/O 与存储开销越大，还可能超过模型最大上下文。现有做法用上下文工程裁剪或摘要历史，但修改轨迹前缀会让后续缓存全部失效，触发昂贵的重新预填充；保留太少又影响准确率。作者提出「缓存工程」：让 Agent 直接控制活跃 KV 缓存而不改轨迹——用 drop 把选定缓存排除出后续注意力，用 repos 调整保留键的位置编码；并识别出「历史依赖」这一服务难题：相同 token 序列在不同缓存操作序列下会产生不同缓存状态，前缀匹配不足以正确复用，因此配套设计了 AKV 服务引擎。实验中，工具响应滚动丢弃策略比常规阈值摘要平均提升 1.7 分、降低 27.7% 成本，吞吐最高 1.2 倍、P95 延迟改善 1.5 倍；缓存策略的递归自改进再降 7.1% 成本。限制是缓存操作需要引擎与模型侧配合，跨供应商 API 难以落地，策略的泛化性也依赖任务类型。

    Cache Engineering for Agents targets KV cache becoming the dominant cost of long agent trajectories: the longer the trajectory, the larger the cache I/O and storage, and it can exceed the model's maximum context. Existing context engineering trims or summarises history, but changing the trajectory prefix invalidates all subsequent cache, forcing costly re-prefill, while keeping too little hurts accuracy. The authors propose cache engineering: agents directly control the active KV cache without altering the trajectory — drop excludes selected cache from future attention and repos adjusts positional encodings of retained keys — and identify history dependence as a serving challenge: identical token sequences produce different cache states under different operation sequences, so prefix matching is insufficient for reuse, motivating the AKV serving engine. Experiments show a tool-response rolling-drop policy improves average benchmark score by 1.7 points while cutting cost 27.7% versus threshold-triggered summarisation, with up to 1.2x throughput and 1.5x better P95 latency; recursive self-improvement of cache policies cuts cost a further 7.1%. The limitation is that cache operations need engine and model cooperation, hard to realise across vendor APIs, and policy generalisation depends on task type.

    边界：限制是缓存操作需要引擎与模型侧配合，跨供应商 API 难以落地，策略的泛化性也依赖任务类型。

    Limits: The limitation is that cache operations need engine and model cooperation, hard to realise across vendor APIs, and policy generalisation depends on task type.

    Proof-Carrying Contracts: Commitments AI Agents Cannot Break

    Proof-Carrying Contracts: Commitments AI Agents Cannot Break

    为什么推给你：Agent 工程（命中：agent、推理、reasoning）

    Why it is here: Agent engineering (matched: agent, 推理, reasoning)

    Proof-Carrying Contracts 针对 Agent 之间的约定只写在自然语言里、无法强制执行的问题：Agent 代人行事后，它可能犯错、被读到的内容改变目标、或追求不同利益；而在一个 Agent 经济里，各方需要无需互相信任对方 Agent 也能依赖的协议。作者提出 Proof-Carrying Contracts（PC2）：在执行任何操作前，Agent 必须提供机器可检查的证明，证明在其模型允许的所有情况下该操作都保持约定约束；执行系统「Airlock」验证证明并控制访问。各方只规定要保持的条件，Agent 自行提供推理并保留策略自由，从而不必再单独设计权限策略并证明其安全。论文证明约束在执行全程成立（即使 Agent 是对抗性的），并给出何时这意味着现实世界中的安全。限制是证明生成依赖对 Agent 行为的可形式化建模，现实系统的模型误差可能让「证明成立」与「实际安全」脱节，工程落地成本也高。

    Proof-Carrying Contracts targets agreements between agents written only in natural language and therefore unenforceable: agents acting on someone's behalf may err, be redirected by what they read or pursue different interests, and an agent economy needs agreements parties can rely on without trusting each other's agents. The authors propose Proof-Carrying Contracts (PC2): before any operation runs, the agent must supply a machine-checkable proof that the operation preserves the agreed constraints in every case its model allows, and an execution system called Airlock verifies the proof and gates access. Parties specify only the conditions to preserve, while the agent supplies the reasoning and keeps strategic freedom, avoiding a separate permission policy plus a proof that every permitted decision is safe. The paper proves constraints hold at every instant even for an adversarial agent and identifies when that implies real-world safety. The limitation is that proof generation depends on formalising agent behaviour, so model error can separate 'proof holds' from 'actually safe', and the engineering cost is high.

    边界：限制是证明生成依赖对 Agent 行为的可形式化建模，现实系统的模型误差可能让「证明成立」与「实际安全」脱节，工程落地成本也高。

    Limits: The limitation is that proof generation depends on formalising agent behaviour, so model error can separate 'proof holds' from 'actually safe', and the engineering cost is high.

    来源：Sources: arXiv
