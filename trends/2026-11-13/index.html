    CoReMem: Cost-Internalizing Memory for Successive Coding Tasks with Prospective Valuation

    CoReMem: Cost-Internalizing Memory for Successive Coding Tasks with Prospective Valuation

    为什么推给你：Agent 工程（命中：memory、记忆）

    Why it is here: Agent engineering (matched: memory, 记忆)

    论文针对的是 编码 Agent 无法判断哪些历史内容值得留给未知的下一任务。CoReMem 用“预期分段价值”比较下一任务带或不带某段历史轨迹的结果，把记忆压缩为仓库位置和可执行检查等锚点，并只在步骤实际使用这些锚点时分配额外价值。在 ChainSWE 上，27B Actor 解决率从 21.0% 提升到 25.7%，步数减少 17%、缓存感知 token 减少 11%。限制是价值估计依赖重复 rollout，短周期能回本不代表任务越多越稳定。

    The paper targets coding agents being unable to decide which repository history is worth preserving for an unknown next task. CoReMem measures prospective segment value by comparing next-task runs with and without pieces of inherited trajectory, compresses memory around repository locations and executable checks, and credits memory only at steps that use those anchors. On ChainSWE it raises a 27B actor's resolve rate from 21.0% to 25.7%, with 17% fewer steps and 11% fewer cache-aware tokens. The limitation is reliance on repeated rollouts, and short-run savings do not guarantee better scaling with more tasks.

    边界：限制是价值估计依赖重复 rollout，短周期能回本不代表任务越多越稳定。

The reference is to tier agents by task difficulty instead of calling the most expensive model at every step; the limitation is that vendor benchmarks and latency advantages still need independent validation on long tasks.
