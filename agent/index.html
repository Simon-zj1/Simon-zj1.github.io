Agent 技术

Agent 的难点从来不只是“会不会调用工具”，而是系统在长链路、失败恢复和权限约束下，仍然能做出可解释、可验证的决策。

从 Demo 到交付，中间隔着一整套系统约束：状态机、降级策略、Trace、评测集、异常恢复与成本边界。

我关注的四层问题

规划与决策

任务分解、计划验证、动态修订和终止条件。比起一次生成完整计划，更重要的是何时重规划。

工具与执行

工具发现、参数生成、权限控制、重试、回滚和失败后的可恢复性，是 Agent 真正进入生产的关键。

记忆与状态

短期上下文、长期记忆、结构化状态与事件回放共同决定系统能否稳定处理长程任务。

评测与观测

成功率之外，还要观察失败分类、工具成本、决策 Trace、延迟和分布外表现。

一套实用的系统路线

  1. 01

    先固定任务边界

    明确可观测状态、动作空间、成功标准和不可逆操作，避免用 Prompt 掩盖系统问题。

  2. 02

    建立事件与 Trace

    让每次观察、决策、工具调用和恢复动作都可追踪，才能定位失败发生在哪一层。

  3. 03

    加入分层降级

    模型失败时退到规则、缓存或人工确认，而不是让整条链路直接中断。

  4. 04

    用实验证明收益

    固定模型、工具和预算，对比流程、记忆策略与恢复机制，记录成本和方差。
